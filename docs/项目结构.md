## 2 工程总体结构（Monorepo）

前后端代码置于同一仓库，前端与后端各自独立管理依赖与构建；`docs/` 存放设计文档，`scripts/` 存放数据库初始化与数据生成脚本。

```

├── AGENTS.md                     # 项目约定（技术栈、规则）
├── README.md                     # 项目说明与启动方式
├── .gitignore                    # 前后端通用忽略规则
├── .editorconfig                 # 编辑器统一风格
├── docs/                         # 设计文档
│   ├── 需求规格说明书.md
│   ├── 概要设计.md
│   ├── 系统架构.md
│   ├── 项目结构.md
│   ├── 接口设计.md
│   └── 数据库设计.md
├── backend/                      # 后端（Python / FastAPI）
├── frontend/                     # 前端（Vue 3 / Vite）

    └── nginx.conf.example
```

**工程约定**

| 项 | 约定 |
| --- | --- |
| 依赖管理 | 后端 uv（`pyproject.toml` + `uv.lock`）；前端 pnpm（`package.json` + `pnpm-lock.yaml`） |
| 运行形态 | 后端单体服务；前端独立构建为静态资源 |
| 环境变量 | 后端 `backend/.env`；前端 `frontend/.env.development`、`.env.production` |
| 忽略文件 | 依赖目录、构建产物、虚拟环境、IDE 配置、日志、本地环境变量文件均纳入 `.gitignore` |

**分层职责（与《概要设计》4.1 一致）**

| 目录 | 层 | 职责 |
| --- | --- | --- |

**前端分层职责**

| 目录 | 职责 |
| --- | --- |
| `api/` | 统一封装请求与响应处理，页面不直接使用 axios |

| `components/` | 可复用组件，统一列表/字典/状态/图表等展示口径 |
| `directives/` | 按钮级权限控制 |

## 5 命名规范

### 5.1 数据库

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 表名 | 小写 + 下划线，单数，语义化；避开 SQL 保留字（订单主表用 `orders`） | `orders`、`order_item`、`sku_mapping` |
| 字段名 | 小写 + 下划线 | `platform_code`、`created_at` |
| 主键 | 统一 `id`（自增整型） | `id` |
| 外键 | `{实体}_id` | `shop_id`、`sku_id` |
| 时间字段 | 创建 `created_at`、更新 `updated_at`、业务时间用具体名 | `paid_at`、`shipped_at` |
| 布尔字段 | `is_` 前缀 | `is_deleted`、`is_abnormal` |
| 金额字段 | `_amount` 后缀，`numeric(14,2)` | `pay_amount`、`freight_amount` |

### 5.2 后端（Python）

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 模块/包 | 小写 + 下划线 | `order_service.py` |
| 类 | 大驼峰 | `OrderService`、`OrderItem` |
| 函数/变量 | 小写 + 下划线 | `fetch_orders`、`shop_id` |
| 常量/枚举 | 全大写 | `ORDER_STATUS_PAID` |
| 接口路径 | 小写 + 连字符，资源复数，统一前缀 `/api/v1` | `/api/v1/orders`、`/api/v1/sku-mappings` |

### 5.3 前端（Vue / TypeScript）

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 组件文件 | 大驼峰 + `.vue` | `PageTable.vue`、`OrderDetail.vue` |
| 目录/页面文件 | 小写 + 连字符 | `views/order/order-list.vue` |
| TS 文件 | 小写 + 连字符或小驼峰 | `datetime.ts`、`request.ts` |
| 变量/函数 | 小驼峰 | `orderList`、`fetchOrders` |
| 常量/枚举 | 全大写 | `ORDER_STATUS` |
| Pinia store | `useXxxStore` | `useUserStore` |

**列表页交互约定**

| 项 | 约定 |
| --- | --- |
| 分页 | 默认每页 10 条，可选 10/20/50/100；请求参数 `page`、`page_size`，`page_size` 上限 100 |
| 操作列 | 操作项按重要性排列，超过 2 项时适当加宽列宽；次要操作收入"更多"下拉 |
| 批量 | 支持多选与批量操作，结果给出成功/失败明细 |
| 状态 | 统一使用 `StatusTag` 展示并按状态配色 |
| 时间 | 统一按 `YYYY-MM-dd hh:mm:ss` 展示 |

## 7 UI 规范与科技蓝主题

### 7.1 主题色（鲜艳科技蓝）

全局主题统一为鲜艳的科技蓝，主色用于主按钮、选中态、链接、图表主系列；通过覆盖 Element Plus 主题变量实现。

| 语义 | 变量 | 色值 | 用途 |
| --- | --- | --- | --- |
| 主色 | `--color-primary` | `#1677FF` | 主按钮、选中态、链接、图表主色 |
| 主色-浅 | `--color-primary-light` | `#E8F1FF` | 选中背景、标签底色 |
| 主色-深 | `--color-primary-dark` | `#0958D9` | 悬停/按下 |
| 成功 | `--color-success` | `#52C41A` | 成功、已完成 |
| 警告 | `--color-warning` | `#FAAD14` | 预警、待处理 |
| 危险 | `--color-danger` | `#FF4D4F` | 失败、异常、退款 |
| 信息 | `--color-info` | `#8C8C8C` | 次要信息 |
| 侧边栏背景 | `--layout-sider-bg` | `#001529` | 深色侧边菜单背景 |
| 侧边栏选中 | `--layout-sider-active` | `#1677FF` | 菜单选中态 |
| 页面背景 | `--layout-bg` | `#F0F2F5` | 内容区底色 |
| 卡片背景 | `--card-bg` | `#FFFFFF` | 卡片/表格底 |

### 7.2 布局规范

| 区域 | 规范 |
| --- | --- |
| 整体布局 | 左侧固定深色菜单（可折叠）+ 顶栏（面包屑/用户菜单）+ 内容区 |
| 内容区 | 卡片式布局，统一内边距 16px，卡片间距 16px |
| 页头 | 列表页顶部为查询区，右侧为操作按钮区 |
| 统计区 | 看板页顶部为指标卡（数值 + 同比/环比），下方为图表 |

### 7.3 组件与图表规范

| 项 | 规范 |
| --- | --- |
| 表格 | 斑马纹可选、表头固定、操作列右对齐固定 |
| 状态标签 | 用 `StatusTag`；订单/售后/库存/同步状态各自固定配色 |
| 金额 | 右对齐、千分位、保留 2 位小数，货币前缀 `¥` |
| 图表 | 统一用 ECharts，封装 `ChartCard`；配色优先取主题色系列，坐标轴/网格统一浅灰 |
| 空状态 | 无数据统一使用空状态插画与"暂无数据"提示 |
| 加载 | 表格用骨架/加载遮罩，避免闪烁 |

### 7.4 状态配色约定

| 场景 | 状态 → 颜色 |
| --- | --- |
| 订单 | 待付款=信息、待审核=警告、待发货=主色、部分发货=警告、已发货=主色、已完成=成功、已关闭=信息、售后中=危险 |
| 售后单 | 待处理=警告、处理中=主色、已完成=成功、已关闭=信息 |
| 库存 | 正常=成功、低于安全库存=警告、缺货=危险 |
| 同步 | 成功=成功、部分失败=警告、失败=危险、执行中=主色 |

## 8 时间与格式约定

| 项 | 约定 |
| --- | --- |
| 后端存储 | 时间统一为 UTC 存储（`timestamptz`），接口以标准时间字符串返回 |
| 前端展示 | 统一格式 `YYYY-MM-dd hh:mm:ss`（24 小时制），由 `utils/datetime.ts`（dayjs）统一格式化 |
| 日期范围查询 | 前端按天选择，后端按 `[起始 00:00:00, 结束 23:59:59]` 处理 |
| 金额 | 保留 2 位小数、千分位，展示统一加 `¥`；接口以数值（Decimal）传输，避免精度丢失 |
| 数量 | 整数展示，不加分隔符 |
| 百分比 | 保留 1~2 位小数，展示加 `%` |
| 单号 | 本地订单号、发货单号、售后单号等由系统按规则生成，全局唯一 |
| 编码 | 平台编码、店铺编码、SKU 编码、SPU 编码为大写字母/数字组合 |

## 9 前端状态管理与公共组件

### 9.1 状态管理（Pinia）

| Store | 内容 | 说明 |
| --- | --- | --- |
| `user` | 用户信息、角色、功能权限码集合、可访问店铺范围 | 登录后拉取，供路由守卫与 `v-permission` 使用 |
| `app` | 布局折叠状态、主题、全局配置 | 控制侧边栏与主题 |
| `dict` | 平台、店铺、订单状态、售后类型等字典 | 首次加载后缓存，减少重复请求 |

**权限落地方式**

1. 登录后调用 `/auth/me` 获取用户信息与权限；
2. 路由守卫校验登录状态，并按功能权限过滤可访问路由；
3. 菜单按权限动态生成；
4. 按钮级权限用 `v-permission="'order:audit'"` 指令控制显隐。

### 9.2 公共组件清单

| 组件 | 用途 |
| --- | --- |
| `PageTable` | 列表页容器：查询区 + 表格 + 分页 + 批量操作统一封装 |
| `QueryForm` | 通用查询表单，支持常用控件与重置 |
| `StatusTag` | 状态标签，按场景统一配色 |
| `AmountText` | 金额/数字格式化展示 |
| `DictSelect` | 字典下拉：平台、店铺、状态等 |
| `ChartCard` | ECharts 图表卡片封装（标题 + 工具栏 + 图表） |

### 9.3 与后端的交互约定

1. 所有请求经 `api/request.ts` 统一封装：注入 Token、统一处理响应体与错误提示；
2. 登录失效（鉴权失败）统一跳转登录页；
3. 分页请求统一携带 `page`、`page_size`，前端限制 `page_size` 不超过 100；
4. 时间字段统一在展示层格式化，不在接口层做个性化处理。
