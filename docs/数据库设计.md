## 2 设计原则与命名规范

### 2.1 设计原则

| 原则 | 说明 |
| --- | --- |
| 单一来源 | 统一订单模型是系统内订单的唯一来源，其他表不重复承载订单数据 |
| 三范式优先 | 关系表满足基本范式；对高频统计仅做必要冗余（如订单号、SKU 编码冗余），冗余字段由服务层保证一致 |
| 主键统一 | 所有表使用自增整型主键 `id`；业务编码另设唯一键 |
| 平台差异隔离 | 平台特有字段存入订单平台扩展表（键值对），不污染统一订单表 |
| 可追溯 | 订单、库存、售后、对账的变更均留日志或流水表，禁止无痕改数 |
| 软删除 | 允许删除的主数据（商品、店铺、用户等）采用软删除标记，业务流水不删除 |
| 金额精度 | 金额统一 `numeric(14,2)`，数量统一 `integer`，避免浮点误差 |
| 时间统一 | 统一使用 `timestamptz`，存储 UTC |

### 2.2 命名规范

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 表名 | 小写 + 下划线，单数、语义化；避开保留字（订单主表为 `orders`） | `orders`、`order_item`、`sku_mapping` |
| 字段名 | 小写 + 下划线 | `platform_code`、`pay_amount` |
| 主键 | `id` | `id` |
| 外键 | `{实体}_id` | `shop_id`、`sku_id` |
| 布尔/标志 | `is_` 前缀或 `smallint`（1 是 / 0 否） | `is_matched`、`is_deleted` |
| 时间字段 | `created_at`、`updated_at`、业务时间用具体名 | `paid_at`、`shipped_at` |
| 金额字段 | `_amount`；数量字段 `_qty` | `pay_amount`、`main_qty` |
| 索引 | `idx_{表}_{字段}`；唯一索引 `uk_{表}_{字段}` | `idx_orders_status`、`uk_orders_order_no` |

### 2.3 通用字段

除纯流水/字典表外，主要业务表统一包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigserial | 主键，自增 |
| created_at | timestamptz | 创建时间，默认当前时间 |
| updated_at | timestamptz | 更新时间，更新时刷新 |

> 主数据表另含 `is_deleted smallint default 0`（软删除）；流水/日志表不含软删除。

## 3 表清单

数据库共 **33 张表**，按 5 个业务域组织。

| 业务域 | 表数 | 表名 |
| --- | --- | --- |
| 平台与店铺域 | 4 | `platform`、`shop`、`sync_task`、`sync_log` |
| 订单域 | 5 | `orders`、`order_item`、`order_ext`、`order_log`、`order_change` |
| 商品与库存域 | 9 | `product`、`sku`、`platform_product`、`platform_sku`、`sku_mapping`、`inventory`、`inventory_flow`、`inventory_share`、`inventory_alert` |
| 履约与售后域 | 5 | `logistics_company`、`shipment`、`logistics_trace`、`after_sale`、`after_sale_log` |
| 财务与系统域 | 10 | `bill`、`bill_detail`、`reconcile_diff`、`user`、`role`、`user_role`、`permission`、`role_permission`、`role_shop`、`operation_log` |

**核心关系**

```
platform 1 ── n shop
shop     1 ── n sync_task       shop 1 ── n sync_log(task)
shop     1 ── n orders          orders 1 ── n order_item
orders   1 ── n order_ext       orders 1 ── n order_log       orders 1 ── n order_change
product  1 ── n sku             sku 1 ── 1 inventory
sku      1 ── n inventory_flow  sku 1 ── n inventory_share   sku 1 ── 1 inventory_alert
product  1 ── n platform_product  platform_product 1 ── n platform_sku
platform_sku 1 ── 1 sku_mapping   sku_mapping n ── 1 sku
orders   1 ── n shipment        shipment 1 ── n logistics_trace
orders   1 ── n after_sale      after_sale 1 ── n after_sale_log
bill     1 ── n bill_detail     bill_detail 1 ── n reconcile_diff
user     n ── n role (user_role)   role n ── n permission (role_permission)   role n ── n shop (role_shop)
```

## 8 初始化与演示数据设计

### 8.1 目标与要求

初始化数据需满足《需求规格说明书》4.3 节要求（覆盖范围、真实性、规模、时间跨度、数据差异、状态完整、关联完整），并支撑软著材料与对外演示。

### 8.2 双模式设计

| 模式 | 用途 | 数据量 | 特点 |
| --- | --- | --- | --- |
| **minimal** | 各批次开发与调试 | 每张表几十条，覆盖全部表与关键状态 | 快速、够用，不追求真实分布 |
| **full** | 交付、演示与软著材料 | 完整规模，覆盖全部表与全部状态/场景 | 贴近真实，体现时间跨度与差异规律 |

**full 模式建议规模（参考）**

| 数据 | 规模 |
| --- | --- |
| 平台 | 5 |
| 店铺 | 12~15（各平台 2~4 个，含自建商城） |
| 本地商品 / SKU | 商品 60~80，SKU 200~300 |
| 平台商品 / 平台规格 | 与本地商品对应，含少量未匹配项 |
| SKU 映射 | 覆盖绝大部分平台规格，保留少量未匹配用于提示 |
| 库存 / 流水 | 全部 SKU 有库存；流水数千条 |
| 订单 / 明细 | 订单 3000~5000，明细约订单数的 1.5~2 倍 |
| 发货单 / 轨迹 | 与已发货订单对应；轨迹每条 5~10 个节点 |
| 售后单 | 覆盖退款/退货退款/换货及各类状态 |
| 账单 / 明细 / 差异 | 覆盖多个账期，含未匹配与金额不一致差异 |
| 用户 / 角色 / 权限 | 用户 10+，角色 6（超管/运营/客服/仓管/财务/只读） |

### 8.3 数据生成规则

| 项 | 规则 |
| --- | --- |
| 随机种子 | 使用**固定随机种子**，保证结果可复现 |
| 幂等与重建 | 脚本支持清空重建（truncate 后重新生成），不写增量补丁；表结构变更时直接改脚本全量重造 |
| 生成顺序 | 平台 → 店铺 → 商品 → SKU 映射 → 库存 → 订单 → 发货 → 售后 → 账单，保证关联完整、无孤立数据 |
| 时间跨度 | 订单时间跨越多个自然月（如近 6 个月），含工作日与促销期（如大促日）差异 |
| 数据差异 | 各平台/店铺在订单量、客单价、商品结构、售后率上存在合理差异，避免平均分布 |
| 状态完整 | 订单覆盖 8 种统一状态；售后单覆盖各类类型与状态；同步日志覆盖成功/部分失败/失败 |
| 关联一致 | 订单明细金额之和与订单金额口径一致；已发货订单有发货单；退货售后有库存回补流水；账单明细金额与订单/售后一致 |

### 8.4 演示数据的内容要点

| 数据 | 内容要点 |
| --- | --- |
| 平台与店铺 | 5 平台、多店铺，含授权状态与启停状态差异 |
| 商品与 SKU | 真实形态的商品名（服饰、数码、家居、美妆等），带规格（颜色/尺码） |
| SKU 映射 | 多对一映射（多平台规格映射同一本地 SKU），保留未匹配样例 |
| 库存 | 部分 SKU 充足、部分低于安全阈值、部分缺货，形成预警与缺货场景 |
| 订单 | 覆盖全部状态，含少量异常订单（地址异常、金额异常、超时未发） |
| 发货与物流 | 多条轨迹节点，含运输中与已签收，含少量物流异常 |
| 售后 | 覆盖退款、退货退款、换货及各类状态，含临近处理时限样例 |
| 对账 | 多账期账单，含已匹配、金额不一致、本地无单/账单无单差异 |

### 8.5 脚本与执行方式

| 脚本 | 作用 | 执行方式（示例） |
| --- | --- | --- |
| `scripts/init_db.py` | 建表（创建全部表与索引） | `uv run python scripts/init_db.py` |
| `scripts/seed_minimal.py` | 生成 minimal 数据 | `uv run python scripts/seed_minimal.py` |
| `scripts/seed_full.py` | 清空并生成 full 数据 | `uv run python scripts/seed_full.py` |
